## 🎯 关键设计决策

### 决策1：为什么是三层架构？

**背景**：AI聊天系统需要处理长连接、流式响应、复杂AI逻辑

**选择**：Client(React) + Server(Node.js) + Agent(Python)

**原因**：
1. **职责分离**：Node.js擅长高并发连接，Python生态更适合AI开发
2. **技术栈匹配**：LangChain等库Python生态更成熟
3. **可独立扩展**：Agent服务可以单独扩缩容

**权衡**：增加了网络延迟，但通过SSE流式响应优化了体验

---

### 决策2：为什么是Qdrant而不是Pinecone？

**背景**：长期记忆需要向量数据库存储语义嵌入

**选择**：Qdrant（开源自托管）

**原因**：
1. **成本**：Pinecone按查询收费，自托管Qdrant免费
2. **数据隐私**：用户记忆数据不外流
3. **可控性**：可自定义索引策略、硬件配置

**权衡**：需要自己维护Qdrant服务，增加运维成本

---

### 决策3：为什么是四层记忆？

**背景**：需要同时支持"当前对话流畅"和"长期用户理解"

**选择**：L1工作记忆 → L2短期记忆 → L3长期记忆 → L4核心记忆

**原因**：
1. **层次分明**：每层有明确的职责和存储策略
2. **性能优化**：L1在内存，L2在SQL，L3在向量库，按需加载
3. **渐进式抽象**：从原始对话 → 语义记忆 → 结构化画像

**对比**：
| 方案 | 优点 | 缺点 |
|------|------|------|
| 单层记忆 | 简单 | 没有持久化 |
| 两层记忆 | 会话内连贯 | 跨会话不理解 |
| **四层记忆** | **全场景覆盖** | **复杂度较高** |

## 🔌 API概览

### RESTful API

| 端点 | 方法 | 说明 |
|------|------|------|
| `/chat/message` | POST | 普通聊天 |
| `/chat/message/stream` | POST | 流式聊天(SSE) |
| `/chat/memories/{user_id}/{conv_id}` | GET | 获取记忆摘要 |
| `/api/public/history` | GET | 公共大厅消息历史（无需认证） |
| `/tools/list` | GET | 列出可用工具 |
| `/admin/reload-prompt` | POST | 热重载Prompt |

### WebSocket事件

| 事件 | 方向 | 说明 |
|------|------|------|
| `authenticate` | C→S | 连接认证 |
| `userMessage` | C→S | 用户消息 |
| `aiStreamStart` | S→C | AI开始响应 |
| `aiStreamChunk` | S→C | 流式内容片段 |
| `aiStreamEnd` | S→C | 流式结束 |
| `publicMessage` | C→S | 公共大厅消息 |
| `publicMessageBroadcast` | S→C | 公共大厅全员广播 |
| `publicAiStreamStart/Chunk/End` | S→C | 公共大厅AI流式响应 |
| `adminDeletePublicMessage` | C→S | 管理员删除公共消息 |
| `adminMuteUser / adminMuteAll` | C→S | 管理员禁言控制 |
